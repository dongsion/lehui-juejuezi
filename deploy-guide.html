小暖咖啡馆点单收银系统 — 单应用部署模式

Vue3 + Express SQLite 数据库 SSE 实时推送 个人收款码支付

0 部署架构

本项目采用单应用部署模式：后端 Express 同时提供 API 服务和前端静态文件托管。只需部署一个服务，无需分别管理前端和后端。

为什么选择单应用？
  • 只需一个部署平台、一个域名、一份配置
  • 前端和后端同源，无 CORS 跨域问题
  • SSE 实时推送在同一域名下工作最稳定
  • 部署、维护、排查问题都更简单

1 推送代码到 GitHub

首先需要把项目代码推送到 GitHub 仓库，Railway / Render 会从 GitHub 拉取代码自动构建。

1.1 创建 GitHub 仓库

  1. 打开 github.com/new 创建新仓库
  2. 仓库名填 baji-ordering（随意）
  3. 选择 Private（私有仓库更安全）
  4. 不要勾选 "Add a README"
  5. 点击 Create repository

1.2 推送代码

在项目目录下执行以下命令（将 你的用户名 替换为你的 GitHub 用户名）：

# 进入项目目录 cd baji-clone # 关联远程仓库 git remote add origin https://github.com/你的用户名/baji-ordering.git # 推送到 GitHub git branch -M main git push -u origin main
提示：如果提示输入密码，GitHub 已不支持密码认证，请使用 Personal Access Token 作为密码。

2 部署到 Railway

2.1 创建项目

  1. 打开 railway.app/new（需注册/登录）
  2. 选择 Deploy from GitHub repo
  3. 授权 Railway 访问你的 GitHub，选择刚才创建的 baji-ordering 仓库
  4. 点击 Deploy Now

2.2 配置环境变量

在 Railway 项目的 Variables 标签页添加以下环境变量：

变量名 值 说明
OWNER_TOKEN my-secret-2026 商家管理端密码，务必改成你自己的复杂字符串
DATA_DIR /data SQLite 数据库存放路径（配合持久化卷）

2.3 添加持久化卷（重要）

Railway 默认使用临时文件系统，重启后数据会丢失。必须添加持久化卷来保存订单数据：

  1. 进入项目的 Settings 标签页
  2. 找到 Volumes → 点击 New Volume
  3. Mount Path 填入 /data（与 DATA_DIR 一致）
  4. Size 选择 1 GB（免费额度足够）
  5. 点击 Add Volume
注意：不添加持久化卷的话，每次 Railway 重启后所有订单和菜品数据都会丢失！

2.4 生成域名

  1. 进入 Settings → Networking
  2. 点击 Generate Domain
  3. Railway 会分配一个域名，如 baji-ordering.up.railway.app
  4. 等待构建完成后，访问该域名即可使用

Railway 会自动执行以下流程：

# 自动构建流程（railway.json 配置） npm run install:frontend # 安装前端依赖 npm run build:frontend # 构建前端 → frontend/dist npm run install:backend # 安装后端依赖（含 better-sqlite3 编译） # 启动命令 node backend/src/app.js # 同时提供 API + 前端静态文件

3 验证部署

部署完成后，用分配的域名进行以下验证：

验证项 访问地址 预期结果
健康检查 你的域名/api/health 返回 {"status":"ok"}
顾客点单页 你的域名/ 显示菜单页面
商家管理端 你的域名/admin 显示登录页，输入 OWNER_TOKEN 登录
菜单接口 你的域名/api/menu 返回分类和菜品 JSON

4 替换你的收款码

系统自带的是示例收款码图片，正式使用前必须替换成你自己的微信/支付宝收款码：

  1. 准备你的微信收款码和支付宝收款码图片
  2. 微信码命名为 wechat-qr.png，支付宝码命名为 alipay-qr.jpeg
  3. 替换 frontend/public/ 目录下的同名文件
  4. 提交并推送代码：git add . && git commit -m "更新收款码" && git push
  5. Railway 会自动重新构建部署
重要提醒：请确保收款码是收款二维码（别人扫码后输入金额付款），而不是付款码。微信可在「收付款 → 二维码收款」中找到。

5 日常使用方式

在微信群推广

顾客端链接：直接把你的域名发到微信群里即可

https://baji-ordering.up.railway.app/

顾客点击链接 → 浏览菜单 → 下单 → 扫码支付 → 点击「我已支付」

商家接收订单

商家管理端：在手机或电脑浏览器打开

https://baji-ordering.up.railway.app/admin

输入 OWNER_TOKEN 登录 → 保持页面打开 → 有新订单时自动响起提示音 + 弹窗通知

使用技巧：
  • 商家端页面保持手机/电脑浏览器常开，有新订单会自动提醒
  • 顾客扫码支付后点击「我已支付」，你这边会收到通知
  • 请到微信/支付宝核对实际到账后再确认订单
  • 在管理端可以查看订单列表、经营统计、管理菜品上下架

备选方案：Render 部署

如果 Railway 免费额度用完，可以换用 Render（有永久免费层）：

  1. 打开 render.com 注册登录
  2. 点击 New + → Web Service
  3. 连接 GitHub 仓库，选择 baji-ordering
  4. 配置如下：
    RuntimeNode
    Build Commandnpm run build
    Start Commandnode backend/src/app.js
    Environment Variables添加 OWNER_TOKEN 和 DATA_DIR=/data
  5. 在 Disk 标签添加持久化磁盘：Mount Path = /data，Size = 1GB
  6. 点击 Create Web Service
Render 免费层限制：15 分钟无请求会自动休眠，下次访问时需等待约 30 秒冷启动。如需 7×24 在线，建议升级为付费层（$7/月起）。
